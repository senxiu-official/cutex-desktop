# 002 收起一个会话

状态：**已实现**（10-22，分支 feat/0.2-tray，待合并；10-21 主人看过 v2/v3：「还可以」，按建议做）。预览：`.claude/preview-tray-taskbar.html` v2（场景「日常」= 左 waveline、右是我 + 我发的 preview）。

## 问题

两个会话并排，我发了一个 preview（开在我这个工作区的 Shelf 里，挤在最右）。主人想暂时把左边的会话收起来给 preview 腾地方，看完再回到双会话。现在只能「关闭」（太重、不好回来）或「独占」（藏在菜单里）。

## 三种做法

1. **收成窄条（基础动作）**：会话列原位收成约 44 px 竖条（像 Shelf 收成 Rail），上面有头像、需要你角标、运行中转圈。入口：标题上的「‹」、把边往外拖过最小宽度吸成窄条、快捷键。点窄条展开，宽度原样。
2. **最小化到托盘**：会话离开屏幕，成为托盘里的「打开着」（001），点它回到原来那一边。腾得更多，但看不到状态。
3. **preview 来时给入口**：show 打开的成果页如果比它舒服的宽度窄，页标题上出现「太窄？收起 X」；点了 = 做法 1，腾出的宽度给这个 preview。**不自动收**（原则：布局只在主人动手时变）。

## 建议

1 做基础，3 做入口，2 用 001 的「关闭 / 最小化」实现。「独占」重新定义为「把其他的都收成窄条」，三者同一套机制。回来：点窄条，或 Alt+←。

## 规则（建议）

- **腾出的宽度给谁**：从 preview 的「收起 X」收的 → 给那个 preview；手动收的 → 按「工作区宽度」设置：铺满时给相邻的列，按内容时露出桌面。
- **收起的是整个工作区**：会话收成窄条时，它的 Shelf 一起收走（不留 Rail），展开时原样回来。
- 窄条状态按对话记，和 Shelf 收起一样存本机。
- 聚焦窄条 = 展开它（窄条不能聚焦着不展开）。
- 两个都收成窄条：不允许，至少一个展开。
- **最后一个会话「—」= 收进托盘并回到桌面**（10-21 主人），不提示「用关闭」。
- 托盘里：收起的会话仍算「在屏幕上」，亮条变成空心（10-22 主人：保持）。

## 实现时定下的细节

- **窄条**：44 px（Shelf Rail 是 48），上面是头像（运行中带转圈环，和侧栏 Rail 同一个信号源）、「需要你」红色数字角标、竖排名字。title「X（已收起）· 点一下展开」。对话本身仍挂着、只是隐藏（滚动位置、草稿都保留）；会话标题不画。窄条那一侧的 Shelf 不画，也不留 Rail / 空 Rail。
- **腾出的宽度**：铺满（智能 / 铺满窗口）时另一列吃掉剩下的全部宽度（不再按拖过的比例分，两列之间的拖柄也不显示）；按内容时另一列保持自己的宽度，整组居中，两边露出桌面。
- **标题按钮**：左列「‹」、右列「›」（尖朝外）只在两个工作区、能收时出现；「—」最小化对任何有智能体的会话都在（只剩一个时 = 收进托盘回到桌面）。顺序：Shelf · ‹/› · — · 放大 · 关闭 · ⋯。这两个按钮**不折进 ⋯**：两个工作区时标题通常已经窄到把服务 / 通知 / 项目都折起来了，再折就等于没有入口；挤的是名字（截断）。
- **独占**：⋯ 菜单里的「独占 / 取消独占」（和 ui-width 的「最大化 = 规则 2」分开；走 lib/paneActions `toggleExclusive` 这一个入口）。两个工作区时 = 另一个收成窄条，再点 = 展开回来；只有一个工作区时仍是原来的「占整行、其他画成 Rail」。菜单项没有悬停预告（菜单不支持）。
- **返回**：Alt+← 也能撤回「收成窄条」和「最小化」（时间线跳转后的「回到」先用 Alt+←，它显示时轮不到这里）。
- **预告**：‹/›、—、放大、关闭、「太窄？收起 X」都有悬停预告，预告和点击来自同一个 effect（lib/workspaceEffects）。
- **「太窄？」的门槛**：Shelf 里的窗格宽度 < 560 px（或它声明的 minSize.w，取大的）。只对「预览类」窗格出现：页面（page:*）、成果（artifacts.view）、网页（browser.tab）、文件预览、diff；终端、文件树、投影的会话不出现。条件还要求另一个工作区能收（makeRoomTarget 非空）。点了：另一个工作区收成窄条，腾出的宽度加到这个 Shelf 上（展开时还回去）。位置在窗格标题下面一行（琥珀色小条）。
- **未读**（10-22 主人定，见文末）：收成窄条 / 只看 Shelf 的会话**不算「在看」**，开始计未读。窄条本身没有拖动菜单（「‹ / ›」的右键见只看 Shelf）。

## 补充（10-22 主人：「会话列似乎也没法最小化」）

场景：只想看 Shelf 里的东西（例如项目 A 的文件树 + 预览，浏览智能体生成的图片），不需要旁边的会话。现在的「收起」把整个工作区（会话 + 它的 Shelf）一起收走，「—」把整个工作区收进托盘——都没有「只收会话、留 Shelf」。

**规则（加）**：
- 会话标题加「只看 Shelf」（⋯ 里，以及 Shelf 展开时会话「‹/›」的长按 / 右键）：**会话列收成原位窄条，它的 Shelf 留在屏幕上并拿走腾出的宽度**（铺满时到整个工作区宽；按内容时到 Shelf 能用的最大宽度）。一个工作区时也可以用。
- 窄条和 002 的一样（头像、需要你、运行中），点窄条 = 会话展开、Shelf 回到原来的宽度。
- 动作预告（008）：灰框框住会话「收成窄条」，蓝框框住 Shelf「变宽到 N px」。
- Alt+← 可撤回。

### 实现时定下的细节（只看 Shelf，10-22，分支 feat/0.2-tray3）

- **入口**：会话 ⋯ 里「只看 Shelf」（它的 Shelf 收着或没有页时灰掉，提示「先展开 Shelf」）；两个工作区时，会话标题的「‹ / ›」右键或长按 = 只看 Shelf（Shelf 没展开时右键 / 长按什么都不做，按钮提示里写着）。只有一个工作区时没有「‹ / ›」，入口只在 ⋯。
- **宽度**：Shelf 的新宽度 = 它现在的宽度 + 会话列让出的宽度（列宽 − 44 px 窄条）+ 这一行里空着的地方（按内容时两边露出的桌面；铺满时没有）。所以铺满时 = 整个工作区宽，按内容时 = 一直宽到这一行放得下为止；最多 1600 px（Shelf 宽度的上限）。新宽度存成这个 Shelf 自己的宽度，原来的宽度记下来，点窄条 / Alt+← 时还回去。两个工作区时**只动自己这一侧**：另一个工作区的列宽不变（规则 3「只改两边的两个面板」）。
- **之后窗口变窄**：按常规宽度规则——Shelf 保持像素宽度；两个工作区时另一列保不住最小宽度，这个 Shelf 就只**画成** Rail（不存），要多出 48 px 才回来（同一套回差）；一个工作区时会话的最小宽度就是窄条的 44 px。
- **预告**：⋯ 里那一行悬停 / 方向键移过去：灰框框会话「收成窄条」，蓝框框 Shelf「变宽到 N px」。N 和真正执行用的是同一次测量（`lib/shelfOnly` shelfOnlyPlan）。「‹ / ›」悬停时仍是普通收起的预告（右键 / 长按没有单独的预告）。
- **回来**：点窄条；Alt+← / 「返回上一个」；在侧栏 / 托盘 / ⌘K 再点这个智能体也会让会话回来（和窄条一样）。窄条状态按对话记、存本机（`cutex-desktop.shelfOnly`），换到别的智能体再回来仍是只看 Shelf。
- **托盘**：只看 Shelf 时托盘图标是空心亮条（和收成窄条一样）。托盘常驻在底部时，如果会话窄得放不下托盘里的东西（例如一个工作区、只剩窄条），托盘退回整条带子（同样有 48 px 回差，不来回跳）。〔038（10-23）起：卡片改为横跨窄条和它的 Shelf，侧栏保持整高；图标放不下收进「… N」。〕
- 只用右边那个 Shelf 拿宽度（两边都展开时）；「只用一个 Shelf」是新安装的缺省，通常只有一个。

## 主人决定（2026-10-22）

收成窄条（以及只看 Shelf）的会话**开始计未读**（不再算「在看」）；托盘空心亮条、窄标题栏截短名字：保持。

### 实现时定下的细节（未读，10-22，分支 feat/0.2-tray4）

- 收成窄条或只看 Shelf 时，这个会话不算「在看」：即使它是聚焦的那个工作区（只看 Shelf 时会话仍是「选中」的），回合结束也会留下未读标记，通知也不再因为「正在看」而压下。窗口重新获得焦点时也不会把它标成已读。
- 窄条上：「需要你」仍是红色数字；没有需要你、有未读时显示蓝色未读数（和侧栏同色）。托盘里的图标照常显示未读点（来自同一套标记）。
- 展开窄条（点窄条、聚焦它、Alt+←、在侧栏 / 托盘 / ⌘K 再点它）或离开只看 Shelf = 又在看了，未读清掉，和选中一个智能体时一样。
- 实现：`lib/foldedTest`（store 的 looksAt 问它）、`lib/convStrips` foldedKeys / useIsFolded；收起的会话不再报告「在屏幕上可见」。
