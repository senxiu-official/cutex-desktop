# 003 最大化 / 独占 / 全屏

状态：**已实现，待合并**（10-22，feat/0.2-width）。决定表 #37。现行实现见 canvas-principles §8.1 第 12 条（旧的「最大化」= 现在要改名的「独占」）。

## 决定

三档：
- **最大化**（单击「放大」）= **规则 2**：被最大化的面板拿到整行所有空隙，其他面板宽度不变、往两边靠贴紧。
- **独占**（⋯ 菜单）：拿走整行，其他面板画成 Rail / 窄条（就是现在的「放大」）。002 定了以后 = 「把其他的都收成窄条」。
- **全屏**（F11 / 长按放大）：只剩它；侧栏收成窄栏、托盘隐藏、顶栏移出布局。

## 规则 2 的细节

- 例：`A 空 B C 空` → 最大化 A = `[A———][B][C]`，B = `[A][B———][C]`，C = `[A][B][C———]`。
- 没有空隙时按钮变灰。
- 两个工作区整行一起算。
- Shelf 里的窗格：竖直方向占满该页（同页其他窗格缩成标题栏）。
- 收起的 Shelf 先展开再最大化。
- 再点 = 还原。~~打开新东西或手动拖边 = 结束最大化~~（10-23 改：最大化后的宽度是真的宽度，见下面「真宽度」）。
- 同一时间只有一个；侧栏和托盘不参与。
- 铺满模式（智能 / 铺满窗口）下：其他会话缩到默认（阅读）宽度，省出空间给它。

## 实现时定下的细节（10-22）

- **入口**：会话顶栏「放大」单击、双击顶栏、Ctrl+Shift+M、Shelf 窗格的 ⤢、Shelf ⋯「最大化 {{shelf}}」、双击 Shelf Rail 空白处 = **最大化**。
  **独占** 在 会话顶栏 ⋯ / 页面顶栏 ⋯ / Shelf ⋯ / 窗格 ⋯ / 页的子菜单里（就是原来的「最大化」，代码 `toggleExclusive` / 侧栏模式 `maximised`，以后改成窄条只动这一处）。独占中按「放大」= 退出独占。长按「放大」/ F11 = 全屏，不变。
- **算空隙**：按内容时 = 桌面露出的所有地方（两个工作区之间、两边）；铺满时 = 其他会话比缺省阅读宽度多出来的部分（阅读宽度 + 卡片边框）。
  最大化 Shelf 时两个会话都算「其他」（都缩到阅读宽度）。一个工作区铺满时最大化会话 = 没有空隙（灰）。
- **灰掉**：空隙为 0 时按钮半透明、提示「没有空隙可占」，单击什么都不做（长按全屏仍可用）。收起的 Shelf 不灰（先展开）；页里不止一个窗格的窗格不灰（竖直方向还能占满）。
- **收起的 Shelf**：展开是真的展开（存）；还原时再收起。
- **什么结束它**：再按一次 / Esc；拖任何一条宽度边或用方向键调宽度（拖动从屏幕上现在的宽度接着拖，不跳）；行里出现新的东西（新会话、新页、新窗格、新标签）；独占 / 全屏开始；被最大化的面板没了或被收起。**关掉别的东西不结束**；切换焦点不结束；窗口缩放保持（每次按新宽度重算）。
- ~~不存盘（重启后没有）。最大化期间外侧边、两列之间的边不显示（拖边会结束它）。~~（10-23 改，见下）
- 代码：`lib/panelGrow.ts`（状态和纯函数）、`lib/panelGrowStart.ts`（结束条件）、`components/side/SideArea.tsx`（行里怎么画）、`components/side/SidePageView.tsx`（窗格占满页）。测试 `test/panelGrow.test.ts`。

## 真宽度（主人 10-23）

主人：「你可以记住旧的方便 restore，但是新的也作为新的参数而不是临时参数」。原因：最大化以前只是「看起来」，一拖边就结束、
面板先跳回原来的宽度再接着拖——主人在 3820 px 宽的窗口上拖会话和 Shelf 之间的缝，Shelf 的外侧边往里缩了约 50 px
（预览里复现：最大化 Shelf 后拖缝，外侧边从窗口边 3792 跳到 2647；最大化会话后拖缝，按下那一刻整行跳回去）。

- **最大化 = 把放大后的宽度存成面板自己的宽度**：一个工作区时会话的宽度（`singleColumnW`）或 Shelf 的宽度；两个工作区按内容时两列各自的宽度，
  铺满时两列的比例；Shelf 的宽度。画面和以前一样（先画一帧放大的样子，同一帧之后存下来，下一帧由存下的宽度画出同样的位置，不跳）。
- **同时记住原来的宽度（还原点）**：会话宽度、两列宽度 / 比例、组的位置、当前会话所有 Shelf 的宽度。
- **拖边不再结束它**：拖的是真宽度，从屏幕上现在的位置接着拖，不跳。外侧边、两列之间的边照常显示。
  Shelf 比宽度上限（1600）还宽时，拖的时候不会被压回上限；往列里拉照样变宽（列让到最小为止，[031](031-edge-push.md)），往外拉变窄。
- **还原**（再按一次 / Esc / Ctrl+Shift+M）：写回记住的宽度——中间拖过也回到最大化之前的样子。按钮在有还原点时一直是按下的。
- **还原点什么时候丢掉**（布局保持现在的样子，按钮弹起）：还原之后；**这一行的面板组成变了**——会话窗格多了 / 少了 / 换了人、
  当前会话的 Shelf 出现 / 消失 / 被收起。Shelf 里开新页、新窗格、新标签**不**算；切换焦点、缩放窗口、独占 / 全屏开关都不算。
- **两个工作区**：整行一起存（按内容：两列宽度；铺满：比例）；最大化的是另一个工作区的 Shelf 时（焦点不在那边）照旧只是画出来、不存。
- **收起的 Shelf 为最大化展开的**：有还原点时仍按「收起」存盘，还原时收回去（规则不变）；还原点因为面板组成变了而丢掉时，它就**真的展开**了（之后按展开存）。
- 不跨重启：还原点只在内存里（重启后宽度是最大化后的宽度，按钮弹起）。
- 代码：`lib/panelGrow.ts`（`restore` / `baked` / `dropRestorePoint`）、`lib/panelGrowStart.ts`（还原点的读写、面板组成）、
  `components/side/SideArea.tsx`（存宽度那一步）、`lib/sideResize.ts`（拖的上限）。测试 `test/panelGrow.test.ts`、`test/maxRealWidths.test.tsx`。

## 修：最大化时闪（10-22）

- 主人报告按「放大」会闪（侧栏也像在闪）。在预览里逐帧记录：原来每个会话各自做「位移 + 宽度」的滑动，在一行里互相牵动——
  第一帧面板先跳开（两个工作区时左边的会话跳了约 277 px，右边的 Shelf 跳了约 131 px），最后一帧再跳回（约 55 px）。
  侧栏本身的宽度、窄栏状态从头到尾没有变，也没有任何面板被重新挂载。
- 现在最大化 / 还原是**整行一起滑**：按下前记下整行的样子，变化后每个面板的宽度和行前面的空白一起从旧值缓到新值（同一条缓动曲线，
  期间不伸缩），每条边都从原位置直线走到新位置，不会先跳再回。代码 `lib/columnGlide` `armRowGlide`；测试 `test/growGlide.test.tsx`。
- 侧栏的自动窄栏不看最大化状态（测试锁住：切换最大化时它连重新计算都不会）。
