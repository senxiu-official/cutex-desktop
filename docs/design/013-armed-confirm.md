# 013 「点两次确认」要让人看懂

状态：**已定方向**（10-22；来源：cutex-setting-UI-2@host02 转达主人确认的问题：同事 0.1.1→0.1.5「更新点一下又变蓝」，主人：「看来这个还得加个引导」）。

## 问题

危险操作用「点两次」确认（`lib/armedConfirm.ts`，`ArmedButton`）：第一次点只是「上膛」，旁边一行红字「再点一次开始：…」，3 秒（`ARMED_TIMEOUT_MS`）后自动复原。同事只点了一次，按钮 3 秒后变回蓝色，以为更新失败了。

## 规则

1. **上膛时按钮本身换字**：「确认更新到 0.1.5」「确认删除」——不只靠旁边一行提示；按钮颜色变成警示色。
2. **看得见的倒计时**：按钮底部一条进度条（或环）在倒数，告诉人它会复原。减少动态时改成「（5）」秒数。
3. **时长按轻重**：一般危险操作 5 s（原 3 s）；**低频大操作（后端 / 应用更新、迁移、删除主机、清除数据）改用对话框**，不用点两次——多一步不烦，且对话框能写清楚后果。
4. **复原时留一句淡提示**：没点第二次就到时，按钮旁留「未开始：需要再点一次确认」约 4 s 后淡出，不让人误以为失败。
5. 键盘：上膛后 Enter / 空格 = 第二次；Esc = 取消上膛。
6. 和 008 动作预告不冲突：上膛期间悬停照常显示预告。

## 范围

- `BackendUpgradePage`（后端更新）、应用更新：改对话框。
- 其余用 `armedConfirm` 的地方（清单：`grep -rln armedConfirm apps/desktop/src`，约 20 处）：统一换成新的 ArmedButton 行为。

## 实现时定下的细节（feat/0.2-armed，10-22）

- **集中实现**：`lib/armedConfirm.ts` 的 `useArmed` 和 `ARMED_BUTTON` / `ARMED_FORM_BUTTON` 带上新行为，所有用点两次的地方自动生效：5 s（`ARMED_TIMEOUT_MS`）；上膛时焦点移到上膛的按钮（Enter / 空格 = 第二次）；Esc 只取消上膛（不再同时关掉对话框 / 菜单）；到时没点 → 按钮旁淡提示「未开始：需要再点一次确认」4 s 后淡出（`ARMED_EXPIRED_MS`）。右键菜单里要点两次的行（`Overlays`）同样处理。
- **倒计时**：上膛按钮底边一条 2 px 白条，5 s 内从满到空（`styles.css .armed-countdown`）；系统选了「减少动态」时改成按钮文字后面的「(5)…(1)」。
- **按钮换字**：多数地方原来就换字（「再点一次删除」「再点一次：升级 3 个」），保留原文案。图标大小的按钮（代码块「运行」、标题栏运行时开关、侧栏卡片 ×）地方不够，仍用浮动提示气泡当说明，但也有警示色和倒计时。「删除互联」上膛后按钮改成「确认删除互联」。
- **改成对话框的**（规则 3 的「低频大操作」）：主机后端更新（更新 / 回滚 / 取消正在进行的更新）、应用更新（侧栏「更新」按钮；原来一点就开始，现在先确认，按钮写「更新并重启」）、运行时迁移（升级空闲的 / 撤销这次升级）、移除主机、删除旧版本。对话框按钮写明动作：「确认更新到 r241」「确认回滚到 r239」「移除并吊销令牌」「删除 3 个旧版本」。
- 其他（删除 MCP 服务器、清除目标、清空暂停队列、停止运行时等）保留点两次 + 新行为。
- 已知：右键菜单里的淡提示会盖住上一行约 4 s（不挡点击）。
