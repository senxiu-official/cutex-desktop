# 031 停止空闲的智能体

状态：**实现中**（10-22，cutex `feat/stop-idle` + 桌面 `feat/0.2-stop-idle`，未部署）。来源：主人 10-22「停止空闲的 agent」：一键，加一个子菜单选「空闲超过……」。

## 问题

在线的智能体即使什么都不做也占内存；智能体之间互相唤醒的名额也被占着（每个项目最多 6 个由智能体唤醒的在线运行时）。现在只能一个一个点「停止」，而且要自己判断哪些真的没事做。

## 做法

### 1. 「停止」有两种

| | 下线（可唤醒）**缺省** | 停止（不自动唤醒） |
|---|---|---|
| 运行时 | 关掉 | 关掉 |
| 之后有委托 / 消息找它 | 按平常的规则自动唤醒（同项目、自己的子智能体，受名额限制） | 不自动唤醒，委托等你上线它 |
| 你给它发消息 | 照常启动 | 照常启动 |
| 和现在的单个「停止」 | 新的 | 一样（记「主人停止」标记） |

只有你亲手审核过启动的智能体（explicit launch，没有可复用的审核记录）本来就只能由你启动：这类智能体在列表里标「只有你能再启动」，选不选由你。

### 2. 什么算「空闲」

全部由 cutex 判断（桌面不重复逻辑）。只看**在线**的智能体。

不能停（列出来，勾不上）：
- 正在跑一回合（包括压缩）、或线程不空闲；
- 有排队的、你发的消息；
- 正在处理别人的委托，或有委托在排队等它；
- 有等你处理的请求（审批、提问）；
- 有在跑的后台子智能体 / 后台命令（停掉会杀掉它们）；
- 空闲时间不够（短于所选门槛）。

可以停但缺省不勾（列出来，说明原因，你可以勾上）：
- 在等自己发出的委托的结果（停掉后结果到了会把它叫醒）；
- 有定好的闹钟；
- 有在跑的作业（作业不受影响，完成后会把它叫醒）；
- 是项目主管；
- 后台情况查不到（运行时太旧或查询失败）；
- 在桌面上钉住的（桌面自己知道钉住）。

只提示、缺省勾上：
- 只有你能再启动（见上）；
- 它开着服务（服务由 cutex 管，停智能体**不影响**服务）。

空闲时间 = 现在 − 最近一次活动（最近一次对话 / 回合结束 / 运行时启动，取最晚的）。

### 3. 范围

当前主机。从项目菜单进入时缺省只看这个项目；确认框里可以在「这个项目 / 所有项目」之间切换（主人 10-23）。「所有项目」= 同一个空闲查询不带项目过滤（cutex 本来就按主机列出所有项目的智能体），停止的请求也是同一个；不新增接口。从主机入口进入时本来就是整个主机，不显示这个切换。

### 4. 界面

- 入口：左侧栏「⋯」/ 主机菜单、项目菜单（只限该项目）、智能体列表。
- 直接点「停止空闲的智能体」= 空闲 **30 分钟以上**的。子菜单：空闲 15 分钟以上 / 1 小时以上 / 6 小时以上 / 1 天以上 / 全部空闲的。
- 空闲多久由主人在对话框里自己选（主人 10-23）：预设 30 分钟 / 1 小时 / 3 小时 / 1 天，或自己填「数字 + 分钟/小时/天」（回车或点「应用」），改了就重新查。菜单进来时带的门槛（含 15 分钟、全部空闲的）照样用，不在预设里时「自定义」框高亮。
- **菜单里就地确认，不弹框**（主人 10-23：风险分级——很高 = 对话框 / 输入字符串，中 = 就地二次确认（013 的 armed），低 = 点一下；停止空闲最多算「中」）：
  - 右键菜单「停止空闲的…（30 分钟以上）」或「按空闲时间停止 ›」里选一个时间：这一行先显示「查看中…」，查完把数字写在行上变成「停止 3 个？再点一次」（警示色，5 秒倒计时，013 的规则）；再点一次才停。0 个 = 这一行写「没有空闲的」，什么也不做。
  - 范围就是这个菜单所属的：项目菜单 = 这个项目；主机入口（侧栏空白处右键）= 整个主机；同样的就地确认。
  - 只停「会停的」那一组（cutex 的 stoppable 且没钉住）；缺省不勾的（含钉住的）和不能停的都不在快速路径里。停止前不再重新列名单，用刚才数的那几个，cutex 仍会逐个重新检查、跳过刚开始干活的。
  - 完成后一条消息条「已下线 3 个」（有被跳过的写「，1 个跳过」），带「撤销」（把停掉的重新上线）。
  - 对话框只留作明确的入口：「选择…」（这个范围）、从项目进来时还有「所有项目…」，用来逐个看、勾选；对话框里的内容（预设时间、自定义、范围切换、撤销）不变。
- 对话框（「选择…」）总会先列出名单再确认（应用自己的，不是系统框）：
  - 列出会停的智能体（名字、空闲多久、项目），每行一个勾选框；
  - 下面列出不能停的和缺省不勾的，带原因；
  - 选「下线（可唤醒）/ 停止（不自动唤醒）」；
  - 按钮写明数量：「下线 7 个」。
- 完成后提示「已下线 7 个 · 撤销」，撤销 = 把这几个重新上线。
- 悬停菜单项时按 008 动作预告描出会受影响的侧栏行（第二期）。

### 5. cutex 接口（能力 `stop-idle-agents`，仅主人）

- `GET /v2/runtimes/idle?minIdleSecs=&projectId=`：每个在线智能体一行：`cutexSessionId, name, projectId, runtime, idleSince, idleSecs, verdict (stoppable | caution | blocked), reasons[]`。
- `POST /v2/runtimes/stop-idle {requestId, sessionIds[], minIdleSecs, mode: "wakeable" | "stopped", dryRun?}`：逐个**重新检查**后再停（刚开始干活的跳过，原因写回）；`blocked` 的一律跳过；`caution` 的只停你勾上的。结果：每个 `stopped | skipped | failed` + 原因。`requestId` 幂等（重放同样的结果）。一次最多 100 个。
- 撤销：对每个已停的发现有的「上线」请求（`cutex/runtime/online`），不另加接口。

## 建议

照上面做，缺省「下线（可唤醒）」+ 30 分钟。

## 决定

待主人确认（下面的待定问题）。

## 规则

1. 只有 cutex 判断谁空闲、能不能停；桌面只显示和传选择。
2. 会杀掉正在进行的工作的（回合、后台子智能体 / 命令、正在处理的委托）一律不停。
3. 确认框总是列出每一个会停的智能体，可以逐个取消。
4. 缺省是「可唤醒」：停了不等于不让它干活。

## 待定问题

1. 缺省门槛 30 分钟合适吗？
2. 主管缺省不勾——要不要干脆不让停？
3. 「在等自己委托的结果」的缺省不勾：其实停掉后结果到了会唤醒它，要不要改成缺省勾上？
4. 要不要以后自动做（例如空闲 6 小时自动下线），还是只保留手动？

## 实现时定下的细节（10-22）

- **撤销放在确认框里**，不是消息条：停完后确认框变成结果（已下线 N 个、跳过的和原因、失败的），按钮「撤销（重新上线 N 个）」/「完成」。现在的消息条只能放文字，加按钮要改公共的提示机制，先不动。
- 菜单项不能「点了直接做」同时「有子菜单」，所以是两行：「停止空闲的智能体（空闲 30 分钟以上）」直接做；「按空闲时间停止 ›」选门槛。确认框里还能改门槛（重新查）。
- 入口：左侧栏空白处右键（当前主机）、项目菜单（替换原来的「停止在线空闲的智能体」；主机的 cutex 没有新能力时保留旧的）、「全部智能体」对话框顶上的「停止空闲的…」。
- 钉住是本机的设置，cutex 不知道：桌面把「可以停」但钉住的改成「缺省不勾」（原因「已钉住」）。这是桌面唯一自己加的判断。
- 「独立智能体」分组：cutex 按项目过滤，独立的（没有项目）由桌面从全主机列表里挑出来。
- 后台作业：从作业服务查（只看最新 500 个作业）；Windows 主机没有作业服务，算 0。
- 动作预告（008，悬停描出受影响的行）留到第二期：受影响的名单要先问 cutex，悬停时不适合发请求。
